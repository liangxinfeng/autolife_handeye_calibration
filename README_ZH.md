# 306手眼标定：自动采集与手动补拍

306一条指令运行：`~/handeye306`。
标准ROS入口：`ros2 launch autolife_handeye_calibration_307 calibration.launch.py`。
首次终端需要：`source /opt/ros/jazzy/setup.bash && source /home/ubuntu/ros2_ws/install/setup.bash`。

新增 **④ 精度验证**：读取本轮/最新外参，显示桌面ArUco位姿，按原板内法线15mm建立夹取中心，先规划再由用户确认运动。不控制夹爪开合；默认预留30mm，完整说明见 [VERIFICATION_ZH.md](VERIFICATION_ZH.md)。仅自碰撞预检，不包含桌面/盒子外部避障；测试结果不等于自动通过精度验收。

## 开始前

图像与关节反馈短暂配对失败时，自动采集先暂停下发新运动目标，最多等待1秒。收到更新且配对差不超过120ms的图像后，重新检查视野并继续当前步骤，不必重开整轮。已下发的小目标可能会完成，并非瞬时刹停。持续配对失败、相机断流、反馈过期或安全检查失败仍停止并保留数据；日志记录时间差供排查。

- 退出VR遥操、控制中心的全身关节模块，保留系统机械臂/视觉服务。程序不会自动杀进程、复位或重启服务。
- 使用头部RGB，不使用VR压缩图。共享内存无画面时，检查系统视觉服务。
- 单片手指上固定轻质刚性板，固定开度。6×6是编码位数，黑框实测边长单位mm；字典DICT_6X6_250，默认自动识别ID。多个码同时出现时只露出本次所用的码，或手动选ID。开始一轮后固定ID，不能混入其他码。
- 工厂内参必须匹配当前相机、图像尺寸和畸变模型；界面勾选检查并不等于已经重新标定内参。
- 自动采集前检查模型路径自碰撞；手动调节和准备复位不做路径规划。所有模式都没有外部环境避障，必须清空桌椅等运动障碍并有人监护实体急停。

## 当前这块板与自动采集

- 2026-09-10实测：左手、黑框57mm、整板75×75mm。计算使用57mm，不能使用75mm。ID仍自动识别。
- 板须刚性固定在**单片**手指上，不要跨两片活动手指固定。采集全程该夹爪240°；重新装板或改变开度必须新建实验。另一只夹爪保持，不自动调整。
- 相机检测最短边放宽到48像素（编码加边框共8格，约6像素/格）；角点误差、平面姿态歧义、停稳和独立验证仍检查。不保证远距离模糊图可用，不预设结果必通过。

操作：准备页核对参数 → 保持式解锁并等待就绪 → 关闭实时调整 → 点击“自动复位→视野内采集20张”。无需再手动点击复位。程序先检查当前姿态到VR初始姿态的路径，自动复位双臂、头部及装板侧夹爪240°；腰腿与另一侧夹爪保持。复位时标定码允许暂时不可见，回到初始位姿后必须清晰识别才能继续。按钮会再次提示清空周围空间和固定板。

默认12张手臂训练＋4张独立验证＋4张头部验证。第16张自动计算外参，只要得到有限、有效的刚体变换，就继续4张头部验证；精度未达推荐值只作提示，不再阻断流程。第20张自动再次计算、保存`calibration_candidate.json`并打开结果页，无需再点计算。结果可用性与精度验证分开显示，不将低精度候选伪装成验证通过，也不自动应用到抓取。数学退化、无效外参和运动安全异常仍停止并保留数据。每个位姿停稳后采8个新帧，保存其中质量最好的一张真实原图，不增加样本数量。自动采集/复位速度参数由15%提升到45%，夹爪准备动作最高25%；这些是厂家反馈限速比例，不保证实际角速度恰好3倍。

复位之后使用当前图像及CAD名义相机轴向，先寻找小范围居中姿态，再选择能完整看见整板的路径。所有中间姿态也检查视野，整板默认留48像素边缘余量；超出边界的候选缩小幅度或换候选，并保持采集姿态多样性。**名义外参仅用于视野预测，不作为最终标定结果。**正式结果仍由实际拍摄图像和反馈求解。

运动中每个新图像重新锚定预测，位置目标最多领先当前实测2°，视觉有效才继续向前发送；临时模糊暂停发送后续目标，持续0.6秒不可靠则停止。靠近边界提前停下；不向视野外盲目追赶整个关节目标。由于相机尚未精确标定，不能保证任何安装方式都完全不会丢码；初始视野不足时给出提示，不放松质量门槛。

正式采集中只运动装板侧手臂与头颈。腰腿、另一只手臂、两只夹爪固定；按已检查的单关节段顺序执行，不由不同关节速度任意切弯。关节反馈偏离轨迹、相机断流、超时或指令被拒绝就停止，不自动恢复追赶。图像不合格最多重试3次，失败保留数据并提示手动补拍。`停止/锁定`取消后续目标，**不是硬件急停**；驱动可能完成已下发的短目标，有危险必须按实体急停。

碰撞检查使用V4简化模型，恢复双夹爪间被忽略的碰撞对，并附加装板夹爪的保守球包络：腕部局部+x方向20cm为球心、半径14cm，附加5mm距离门槛。**这是保守假设，不是实测安装外参**；板/支架不得超出该包络，外部桌椅不在模型中。改变板或安装位置需重新检查，不可为通过检查而直接缩小包络。最终标定FK仍使用带完整头部相机链的厂商URDF。

路径检查为独立只读进程，分为复位路径检查与复位后的采集路径检查，每阶段最长120秒；检查期间姿态改变超过0.5°即作废，不发送目标。使用几何包围盒提前排除确定不可能接近标定板的网格，再对其余网格精确检查；检查密度0.5°、碰撞对和余量不变。相同输入的重复状态仅在本次检查中复用，不跨机器人姿态复用旧结果。离线失败轮记录回放：复位路径约0.6秒、完整采集路径约1.8秒，另有进程加载和停稳时间；不是承诺所有起点耗时相同。每轮保存`auto_plan.json`与实际样本，计算结果仅输出候选文件，不自动写入抓取系统。自动模式只限本次20张方案；旧38张手动实验仍可加载。

## 操作

1. ①准备：选装板手臂、实测黑框尺寸，ID默认自动；核对安装和相机参数，然后进入调姿。
2. ②调姿与采集：实时RGB旁显示三维机器人。实体色模型来自反馈，蓝色虚影是目标。夹爪10°全开、360°全闭，有两侧全开/全闭目标按钮。模型端点按URDF手指表面间距修正为全闭0、名义全开95mm，但电机角到真机指间宽度尚未实测标定，不能用于测量或碰撞判断。
3. 点击“解锁手动调整（保持当前）”，确认安全并等待就绪。勾选“实时调整”后，拖动滑块/数字框/模型即发送低速目标；未勾选时只预览，需要点“发送预览目标”。勾选时同步当前实测，不执行之前遗留的目标。松开滑块会完成当前目标，需停止时点“停止/锁定”。

   调整速度默认100%，与控制中心普通关节调节相同（指令10Hz、身体反馈领先上限5°、夹爪30°，仍受厂家运动约束，不等于固定的物理角速度）。可在界面调低至10%；对下一次目标发送生效。复位独立使用50%，不随普通调节提速。
4. 可点“回到VR初始姿态”，确认后双臂收拢、头部俯视20°，装板侧夹爪240°，腰腿和另一侧夹爪保持。复位不会自动解锁，没有碰撞路径规划。必须确认双臂和标定板沿途无障碍；采集期间需先结束本轮才能复位。
5. 调好头部和夹爪，点“姿态准备好了·开始本轮采集”。记录固定基准并锁定；如需调整手臂，再显式解锁和勾选实时。固定阶段禁止调整颈部/夹爪，避免混合不一致的样本。

   点击后没有开始时会弹出具体原因，缺准备勾选项会回到①准备页。开始仅要求识别唯一ID和机器人停稳，不要求第一帧PnP质量通过；正式记录每张图仍必须通过全部质量检查。
6. 1~24张按当前提示改变位置和板倾角；停稳后记录。约1秒内采8个独立帧，通过检查后保存一张真实原图，自动进入下一条提示；不会自动运动。
7. 25~32张独立验证，保持头部不变。完成后进入③评估与重拍，计算并检查结果；33~38张再转头验证。全部拍完重新计算。
8. 双击评估表异常行回到该张重拍，或选缩略图查看旧图。替换保留旧图并使旧结果失效，需要重新计算。不能靠排除失败验证样本凑通过。
9. 换板尺寸/开度/固定方式需“结束本轮/重新准备”。已有实验可从①准备页继续。

如显示“目标已发送但实测关节5秒无跟随”，程序会锁定，不会不断追赶。检查驱动使能、故障和机械阻挡后再试。它与“仅预览未发送”不同。程序不自动清错，不关闭或重启厂商服务。

## 保存与评估

数据默认放在`/home/ubuntu/ros2_ws/src/autolife_handeye_calibration_307/sessions/时间/`，包括原始PNG、session.json、calibration_candidate.json。记录K/D、真实关节/FK、接收时间来源、图像帧号、角点及替换历史。

候选结果采用`T_A_B`把B坐标变换到A，平移单位m；同时输出躯干到相机、头部安装坐标到相机、腕端到标定板的变换。不会自动应用到机器人、不会把未通过验证的结果伪装成成功。

固定头部eye-to-hand使用两种OpenCV方法交叉比较，独立验证样本不参与拟合。初始通过门槛见config/experiment.yaml（位置P95≤10mm、角度P95≤2°、投影P95≤3px，至少6个验证样本）。这些是内部一致性门槛，不是实际抓取精度保证。真实TCP、深度比例/对齐、机械间隙和关节零偏需另行验证。

如大量样本提示姿态太相似/旋转方向单一，增加位置和倾斜方向差异；不要仅删除失败验证样本凑通过。转头误差大时检查头部零偏/运动学，而不是强行使用固定相机TF。

## 依赖与约束

ROS2 Jazzy、control_center_joint_control、python3-pyqt5、python3-opengl、python3-opencv（含aruco）、python3-scipy、python3-yaml。自动预检额外复用openarmx_teleop_vr_306_v4的碰撞模型和robot_env的Pinocchio/hpp-fcl；缺失时拒绝自动运行，不降级为无碰撞运动。使用306已安装厂商camera_shm扩展，只读取图像。支持OpenCV4.6旧版及新版ArUco检测接口。

程序使用系统Python，按需加载robot_env内ABI兼容的posix_ipc扩展；不把整个Conda环境加入搜索路径，以免覆盖系统Qt、NumPy和ROS依赖。

使用完整厂商URDF，不使用缺相机链的V4简化URDF；记录URDF哈希。当前默认不叠加旧抓取包[0,-1,4]头部补偿；固定头部结果先验证，再评估不同头部角度。

时间戳目前为共享内存读取及关节接收时刻，并非硬件同步时间；通过停稳采样减小影响。不得据此宣称已完成动态标定。

参考：[OpenCV手眼标定](https://docs.opencv.org/4.12.0/d9/d0c/group__calib3d.html)、[PnP/IPPE](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)。
